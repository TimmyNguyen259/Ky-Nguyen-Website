If no one can say which judgment should improve, who owns it and what evidence would change their mind, another tool will only make the old process move faster.

Most rollouts stall in the same place. A team names an AI capability, picks a tool and a pilot team, and then discovers the real problem was never adoption. The decision the tool was supposed to sharpen was never defined. So the pilot returns better inputs into a process that still cannot say which decision changed as a result.

The corrective is upstream of the tool. Before AI enters a workflow, three questions have to have real answers, written down:

**Which judgment is this meant to improve?** Not “efficiency” or “quality” — the specific call someone has to make.

**Who owns that judgment?** If ownership is diffuse, no one benefits from a better input and no one is accountable for a worse one.

**What evidence would move it?** If the answer is “more confidence”, the judgment is not yet real. Real judgments have failure modes that a specific piece of evidence could change.

> Start with the decision. Then decide whether AI belongs in the system.
